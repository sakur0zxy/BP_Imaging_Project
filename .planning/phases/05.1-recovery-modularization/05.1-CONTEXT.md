# Phase 5.1: Recovery Modularization - Context

**Gathered:** 2026-04-22  
**Status:** Ready for planning  
**Source:** In-thread architecture discussion + live codebase audit

<domain>
## Phase Boundary

本 phase 只负责把当前已经可用但偏 CS 专用的恢复层，重构成一个长期可扩展的通用 `recovery/` 模块。  
目标不是新增恢复算法，也不是同时完成恢复效果评测模块，而是先把恢复层的外部接口、目录结构、配置契约和内部职责拆清楚。

本 phase 应覆盖：
- 新官方目录 `src/recovery/`
- 新官方入口 `run_recovery(...)`
- 新方法命名 `cs_1d`、`cs_2d`
- 新 recovery 配置结构
- real/sim pipeline 切到新入口
- 测试、文档和旧 `src/cs_recovery/` 的清理

本 phase 不覆盖：
- 新的非 CS 恢复算法实现
- 恢复效果评测模块
- Phase 6 中完整图 / 缺失图 / 恢复图的对比输出整理
</domain>

<decisions>
## Implementation Decisions

### 长期架构方向
- **D-01:** 恢复层现在直接升级为通用 `src/recovery/`，不再保留 `src/cs_recovery/` 作为正式结构。
- **D-02:** 主流程以后只允许调用一个恢复入口：`run_recovery(sourceData, recoveryConfig, referenceSourceData)`。
- **D-03:** 新正式方法名固定为 `cs_1d`、`cs_2d`，不再把 `1d`、`2d` 作为正式接口。

### 配置与契约
- **D-04:** recovery 配置改为两层结构：`recovery.common.*` 与 `recovery.methods.<method>.*`。
- **D-05:** 本次重构不保留 recovery 旧字段兼容；默认配置、校验、测试和文档统一切到新结构。
- **D-06:** 所有恢复方法最终都必须输出统一的 `recoveryResult` 结构，至少包含 `status / reason / method / echo / sourceData / recoveryInfo / metrics`。

### 模块边界
- **D-07:** `recovery/` 只负责恢复问题构造、方法分发、具体恢复算法和统一结果封装，不负责 BP 成像、分析绘图和结果目录管理。
- **D-08:** `solvers/` 与 `transforms/` 不继续挂在 recovery 顶层，而是作为 `methods/cs/` 的内部实现细节。
- **D-09:** 指标计算和结果封装独立成 `result/` 层，避免不同方法各算一套结果。

### 与后续 phase 的关系
- **D-10:** 恢复效果评测模块仍属于 `analysis/`，单独作为 Phase 6 的工作，不混入本 phase。

### the agent's Discretion
- `recover_cs_1d.m` 和 `recover_cs_2d.m` 内部是否进一步抽更多小函数，可由实现时决定，但必须保证外层目录骨架稳定。
- `prepare_recovery_config.m` 中的默认值补齐粒度可由实现时决定，但必须统一承担“补默认值 + 抽方法参数 + 校验”三件事。
</decisions>

<specifics>
## Specific Ideas

推荐目标结构如下，注释说明了每一部分的职责：

```text
src/recovery/
├── run_recovery.m                          % 恢复模块唯一入口；pipeline 只调这个
├── build_recovery_problem.m                % 把 sourceData/referenceData 整理成统一恢复问题
├── prepare_recovery_config.m               % 补默认值、抽方法参数、校验 recovery 配置
├── get_recovery_registry.m                 % 注册表：方法名、说明、处理函数、参数入口
│
├── shared/
│   ├── resolve_observation_mask.m          % 统一观测掩码格式
│   └── get_method_config.m                 % 读取当前 method 对应的参数块
│
├── result/
│   ├── compute_recovery_metrics.m          % 统一恢复指标
│   └── pack_recovery_result.m              % 统一封装 recoveryResult
│
└── methods/
    ├── cs/
    │   ├── recover_cs_1d.m                 % CS 1D 恢复方法
    │   ├── recover_cs_2d.m                 % CS 2D 恢复方法
    │   ├── solvers/
    │   │   └── run_fista_sparse_recovery.m % CS 家族共享 FISTA 求解器
    │   └── transforms/
    │       ├── transform_azimuth_fft.m     % 方位向 FFT 变换
    │       ├── inverse_transform_azimuth_fft.m % 方位向 FFT 逆变换
    │       ├── transform_fft2d.m           % 2D FFT 变换
    │       └── inverse_transform_fft2d.m   % 2D FFT 逆变换
    ├── interp/
    │   └── recover_interp_azimuth.m        % 未来非 CS 方法占位
    └── tv/
        └── recover_tv_2d.m                 % 未来非 CS 方法占位
```
</specifics>
